Features

Every page works the same way on both engines: a short row of tabs, a grid you can sort, filter and export, and colour only where something needs you.

The fleet at a glance

The Summary counts every check across the fleet and lists one row per server. The Performance summary puts CPU, waits and IO of every server side by side. Tags such as prod or team:billing group the tree and filter every fleet page.

Running queries and blocking

Every session each minute, the blocking chain to its head, the head's last statement, and the waits of each victim. Earlier minutes stay one click away. Cancel or end a session from the page when you turn that on.

Statements and slow queries

The statements that cost the most over any window, as real per-interval numbers from pg_stat_statements, with each statement's trend. Slow statements, deadlocks and failed logins from the server log; on SQL Server from small Extended Events sessions.

Performance and metrics

CPU, sessions, waits, transactions and IO on one time axis, a Metrics grid with the current, minimum, maximum and average of every counter, host CPU and memory, and IO by type.

Jobs and backups

SQL Server Agent, pg_cron and pgAgent jobs: every run, the failed step's error message, a timeline, and the definition's changes. Backups and WAL archiving with their age, and RDS and Aurora snapshots.

Storage and growth

Every volume with its growth per day and the days until it is full, the largest tables across the fleet, database sizes over time, and on SQL Server the data and log files, TempDB and the version store.

Replication and availability

Streaming and logical replication, slots and the WAL they hold, Aurora replicas; on SQL Server Always On, mirroring, log shipping and replication.

Configuration and changes

Settings with a history of every change, server properties, roles and permissions, schema changes, and a side-by-side diff of two servers or of one server at two times.

Health checks

Vacuum and wraparound, unused and duplicate indexes, versions against the release calendar, extensions out of date, corruption signs, and your own SQL as a check with its own thresholds.

Alerts and exports

A rule on any metric for a server, a tag or the fleet, sent by email, Teams, Slack, a webhook or a file. Every grid exports to Excel with its colours, or to CSV.

Cloud

On RDS and Aurora the server log from CloudWatch, storage IO, Performance Insights kept past its seven days, and AWS DMS tasks with their lag and how long they need to catch up.

If you already run other tools

A site that runs DBA Dash sees its SQL Server instances in the same tree. Grafana can read the same database through ready-made dashboards. An AI assistant on the same machine can read it through a read-only MCP server.

What it reads

The full list of what is collected from each engine, how often and with which right, is in the documentation: PostgreSQL and SQL Server.
